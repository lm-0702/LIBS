01 · About LIBS

A page builder, not another monthly bill.

LIBS is a desktop-style page editor for creating a personal landing page that brings your online presence together. Add your profile, content, links, products and embeds, preview the design, and export a standalone website file.

One purchase. Keep using the app.

LIBS is offered as a one-time purchase. After buying, you can continue using the app without a recurring LIBS subscription. There is no monthly LIBS software fee.

Hosting is separate

Your exported page is a website file. You choose where to host it. GitHub Pages offers a hosting option; domain registration, if you buy a custom domain, is a separate service and may have its own renewal cost.

Important: “No monthly LIBS fee” refers to the app licence. Third-party services such as domain registrars, paid hosting providers, or analytics services may have their own terms and charges. GitHub Pages availability and limits are controlled by GitHub.

03 · First steps

From blank canvas to published page.

You do not need to write website code. Prepare your content, use the app's editor, and follow the publishing steps below.

Get and open LIBS

Use the Get LIBS button to visit the official purchase page. After purchase, follow the delivery instructions supplied on that page to download and open the app. Keep your original download and a backup of your project in a safe place.

Choose a theme

Start with a theme, then adjust the appearance to suit your personal brand, creator profile, business or project.

Set up your profile

Add your display name, bio, profile photo, optional PNG frame, banner, alignment and other available appearance settings. Use a clear image you have permission to use.

Add your content

Create your social links, main call-to-action buttons, notes, dividers, media embeds, product cards and decorative stickers. Check every destination URL carefully.

Add a favicon and analytics (optional)

Upload a small browser-tab icon if you have one. If you want traffic measurement, create a Google Analytics 4 property and paste its Measurement ID (usually begins with G-) into the app's Analytics field.

Preview and export

Review the page at desktop and mobile widths. Test buttons, social links, product destinations and embeds. Export the website and keep the generated index.html file.

Publish and test the live URL

Upload index.html to your hosting provider. Open the public URL on a phone and computer, test all links and confirm that your images and embeds load correctly.

04 · Publish with GitHub Pages

Make your page live on GitHub.

GitHub Pages can publish a website from a repository. The steps below describe the standard repository workflow; GitHub may update its interface over time.

Create or sign in to GitHub

Go to github.com and create an account or sign in. Verify your email if GitHub asks.

Create a new repository

Choose New repository, give it a simple name such as my-bio-page, and create it. For a straightforward GitHub Free setup, use a public repository unless your plan and current GitHub Pages rules support the private-repository option you need.

Prepare the complete website package

After exporting from LIBS, open the export location and look at everything that belongs to the website. You must upload index.html AND every separate media/asset file or folder that the page uses—for example, locally stored photos, banners, thumbnails, icons, background images, or other exported assets. If the app/export gives you an assets or media folder, keep that folder and all its contents. Do not upload only the HTML file when it depends on separate files.

Upload index.html and media together

In your GitHub repository, choose Add file → Upload files. Select index.html and all related media files/folders in the same upload. Keep the folder names and structure the same as in the export. For example, if the HTML expects assets/profile.jpg, the repository must contain an assets folder with profile.jpg inside it. Put index.html in the repository root (top level), unless you intentionally configured a different publishing folder. Commit all files together.

Know which media needs uploading

Upload local files: images or other files saved with the website export, and any separate files referenced by the page. External media: a YouTube/video embed or image hosted on another public service may load from its provider and may not need to be uploaded to GitHub. It still needs a correct working URL and the provider must allow embedding/access. When unsure, include the separate media files supplied with your export and preserve their paths.

Enable GitHub Pages

Open the repository's Settings → Pages. Under the build/deployment source, choose Deploy from a branch, select the branch containing your file (commonly main) and folder /(root), then save.

Wait for deployment and open your URL

GitHub will show the Pages site address in the Pages settings after deployment. It often looks like https://YOUR-USERNAME.github.io/REPOSITORY-NAME/. The first publish can take a few minutes. Refresh the Pages settings if the link is not ready yet.

Update your page later

Edit your design in LIBS and export again. Upload the new index.html to the same repository and commit the replacement. GitHub Pages will publish the updated version.

05 · Custom domain

Use your own web address.

Instead of the default GitHub Pages address, you can connect a domain you own, such as yourname.com or links.yourname.com.

Buy or use a domain you control

Register a domain through a domain registrar, or use one you already own. Domain registration is separate from LIBS and may renew annually.

Add the domain in GitHub Pages

In your repository, open Settings → Pages. Find the Custom domain field, enter the domain you want to use, and save. Follow GitHub's current instructions for the exact domain type you selected.

Set the DNS records at your registrar

Open the DNS management page where your domain is registered. For an apex/root domain such as yourname.com, GitHub documents A records (and supported AAAA records). For a subdomain such as links.yourname.com, GitHub commonly uses a CNAME record pointing to YOUR-USERNAME.github.io.

Use the exact current record values shown in GitHub's official documentation. Do not copy random DNS values from another website.

Wait for DNS and enable HTTPS

DNS changes can take time to propagate. Return to Settings → Pages and, when available, enable Enforce HTTPS. Check the site using the custom domain after the change completes.

DNS Setup Quick Reference

Domain Helper

Point your root domain (@) using the official A / AAAA records listed in GitHub's documentation:

Type: A | Host: @ | Value: (See GitHub's current official A record IP list)

Point your subdomain host (such as links) via a CNAME record to your GitHub Pages domain:

Type: CNAME | Host: links | Value: YOUR-USERNAME.github.io
DNS records depend on whether you use an apex domain or a subdomain and on your DNS provider. Follow GitHub's custom-domain guide and its linked DNS instructions for the current exact values.
06 · Analytics

Connect Google Analytics 4.

Analytics is optional. It can help you understand traffic to your published page, subject to Google's setup, privacy and consent requirements that apply to your audience and location.

Create a GA4 property

Sign in at Google Analytics, create an account or property, and add a Web data stream for your published website URL.

Copy the Measurement ID

In the Web stream details, find the Measurement ID. It usually looks like this:

G-XXXXXXXXXX

Paste it into LIBS

Open the app, find Optional Google Analytics, paste the Measurement ID into the field, then export your page again.

Publish and verify

Upload the newly exported index.html. Use the Realtime report in Google Analytics to check whether visits are being received. Data may not appear instantly.

Google's official help: Set up Analytics for a website.

07 · Plan your page

Prepare your content before you start.

A little planning makes building much easier. Decide what visitors should do first, then organize your page around that goal.

Choose one main goal

Examples: send people to your newest video, contact you, view your portfolio, browse your products, book a service, or visit your community. Make the most important action easy to spot.

Collect your links

Write down the full URLs for your social profiles, website, shop, portfolio, contact method and other destinations. Open each URL yourself before adding it.

Prepare your images

Choose a profile image, optional banner, product thumbnails, sticker artwork and favicon. Use files you own or have permission to publish.

Write your bio

Use a short introduction that explains who you are and what visitors can find on the page. Keep important information near the top.

Organize your blocks

Group related links and content. Put the most useful destinations first and avoid adding so many buttons that visitors cannot decide what to tap.

Check mobile readability

Most visitors may open a bio link from a phone. Use readable text, clear contrast, appropriately sized images and concise button labels.

Suggested content checklist: display name · short bio · profile photo · optional banner · primary link · social profiles · supporting links · product or portfolio details · favicon · analytics ID (optional).

08 · Feature-by-feature tips

How to use the building blocks.

These explanations describe what each type of content is for and how to prepare it. The exact control names and available choices are shown inside your installed LIBS version.

Profile name, description and bio

Your profile area introduces the person, brand or project behind the page. Use a recognizable display name and a short bio. Explain what you create or offer and give visitors a reason to explore your links. Avoid putting private information on a public page.

Profile image, avatar frame and banner

Use a clear square profile image where possible. If you add a decorative frame, use a transparent PNG so the photo can show through the transparent area. A banner is a wider visual area that can show a brand image, announcement or theme. Preview images at phone size because cropping can vary by screen.

Theme, colors, fonts and alignment

Pick a consistent palette and use it across the page. Keep text and button contrast strong enough to read. Use one or two font styles rather than many competing styles. Alignment settings help establish a visual structure; check both narrow and wide previews after changing them.

Link buttons and social profiles

Give each button a clear label such as “Watch my videos”, “View my portfolio” or “Contact me”. Paste the complete destination URL, including https:// where appropriate. Test every button after export. For social links, use the correct profile address rather than a search result or an unrelated post.

Notes, headings and dividers

Use notes for short announcements, context, disclaimers or instructions. Dividers help separate groups of content. Keep paragraphs short so the page remains easy to scan on mobile.

Media and embedded content

There are two common cases. 1) Separate/local media files: if your page uses photos, banners, icons, thumbnails or other files stored alongside the exported site, upload those files to GitHub with index.html. Keep the same folder structure and filenames; do not rename or move them after upload unless you also update the references in the page. 2) External embeds/hosted media: a YouTube embed or media hosted by another service usually loads from that provider, so you generally do not upload the provider's video file to your repository. Use the correct public share/embed URL and check that embedding is allowed. Test the live HTTPS page because provider settings, privacy, browser restrictions or regional availability can affect playback.

How can I check that I uploaded every media file?

Compare the files in your export folder with the files shown in your GitHub repository. Confirm that index.html is present, every accompanying assets/media folder is present, and the folder structure is unchanged. Open the published page and check every image and media area. If something is missing, inspect the related filename and path, upload the missing file, and commit the change.

Product cards and store links

Use product cards to present an item or offer with an accurate title, image, price information and a working destination. Confirm that prices and availability are current. LIBS displays the information you enter; checkout, payment processing, fulfilment and refunds are handled by the external store or service you link to.

Stickers and decorative artwork

Stickers add personality and visual emphasis. Use them sparingly so they do not cover important text or make the page harder to navigate. Keep decorative assets appropriately sized and use artwork you have permission to publish.

Favicon

A favicon is the small icon shown in a browser tab, bookmark or shortcut. A simple square icon with a recognizable shape usually works best. After publishing, browsers may cache the old favicon; allow time or refresh the browser cache before deciding it failed.

Project backup and restore

Use the app's JSON backup/restore feature to preserve editable project settings. Store a backup before major redesigns and keep copies of the image files used in your page. The exported index.html is for publishing; it is not a substitute for your editable project backup.

09 · Export and launch checklist

Check the page before sharing it.

Your exported website is the public-facing version of your design. The editing workspace stays in the LIBS app; visitors receive the published page only.

Before export

  • Check spelling, profile details and button labels.
  • Open each destination URL and confirm it is correct.
  • Check image quality and cropping.
  • Confirm embeds are allowed by their providers.
  • Check optional analytics settings.
  • Save an editable backup of your project.

After export

  • Keep the file named index.html.
  • Keep all separate media/assets files and folders used by the page.
  • Open it locally to inspect the page layout.
  • Test links, buttons, social destinations and media.
  • Check on a phone-sized screen and a desktop.
  • Upload index.html and all required media/assets together, preserving folders.
  • Test the final public HTTPS address.

11 · Troubleshooting

Quick fixes for common issues.

My GitHub Pages link shows a 404 page.

Confirm Pages is enabled in Settings → Pages, the correct branch and folder are selected, and index.html is in the publishing root. Check the deployment status and wait a few minutes after committing.

My images or embeds are missing.

Check that the original media is included or accessible as expected, that external URLs are correct and publicly reachable, and that the embed provider allows embedding. Some providers block embeds or require their own settings.

A YouTube embed does not play in the editor preview.

Some browser/file preview contexts restrict embedded media. Test the exported page from a web server or its published HTTPS address. Playback can also depend on YouTube availability, privacy settings, browser restrictions and the embed URL.

My changes are not visible on the live page.

Export again after editing, replace the existing index.html in the correct repository location, commit the change, wait for deployment, then refresh the page. A browser cache may show an older copy temporarily.

Can visitors rearrange or edit my published page?

The exported public page is intended for visitors and does not include the app editor's layout-arranging controls. Visitors can use the links and interactive content you publish. However, the owner of the GitHub repository or hosting account can always edit or replace their own website source.

Can I change the page after publishing?

Yes. Reopen your LIBS project, make the changes, export a fresh index.html, and upload the replacement to your hosting repository.

Do I need to pay every month?

LIBS is positioned as a one-time app purchase with no recurring LIBS subscription. Your hosting provider, domain registrar or other third-party services may have separate fees or limits.

12 · FAQ

Good to know before you publish.

What is LIBS for?

It is for creators, freelancers, small projects and anyone who wants one customizable page that gathers their important links, profile details, content and product destinations.

What do I receive after buying?

Use the purchase page's delivery instructions for the current download and access details. This support page does not process orders or deliver the app itself.

Is GitHub part of LIBS?

No. GitHub is a separate third-party service. LIBS creates the page file; you manage your own GitHub account and publishing settings.

Does the exported page include the editor?

No. The export is a visitor-facing website, not the editing application. Keep the app and your editable backup if you want to make future changes.

Can I use another host?

Yes. The exported HTML is intended to be a standalone website file and can be uploaded to a compatible web host. The exact steps depend on that provider.

What should I keep backed up?

Keep your original app download, editable project data/JSON backup, exported website file, and copies of images or other media you used.
